.. py:class:: EtnFile

    A ``.etn`` file named once, for the backings of its entries.

    Holds only the path: nothing is opened until a backing is built, and each backing reopens the
    file by path at every slab as ``etn_backing``'s do. A program that keeps several tensors in one
    file names it here rather than in every backing.

    .. code-block:: text

       ints = einsums.io.EtnFile("ints.etn")
       B = graph.declare_tensor("Bvv", backing=ints.entry("Bvv"))
       T = graph.declare_tensor("T2", dims, backing=ints.entry("T2", write=True))

    .. versionadded:: 2.0.0

        Name the file.

        :param path: The file, stored as given; see ``etn_backing``.

.. py:class:: TensorFile

    A handle on an ``.etn`` file.

    Writing, rewriting and reserving entries change the handle's own table until it commits, which
    ``close``, ``flush`` and the destructor do, and each entry operation (``rename``, ``swap``,
    ``copy``, ``remove``, ``restage``, ``compact``) does before it returns. A commit puts new data
    and a new table into space the file's last commit does not use and then rewrites the header, so a
    process that stops at any point leaves the file as its last commit left it. With
    ``--einsums:io:sync`` on, the default, a power loss does too. A handle refuses to commit over a
    file another handle has committed to since this one last read it.

    .. py:method:: rename(old_name: str, new_name: str) -> None

        Give the entry ``old_name`` the name ``new_name``.

        Only the entry table changes, so a rename costs the same whatever the entry holds. It is
        committed before this returns. Renaming an entry to its own name does nothing.

        :raises Exception: when there is no entry ``old_name``, or the file is open for reading.
        :raises Exception: when an entry is already named ``new_name``, or no entry can hold that name.


    .. py:method:: swap(first: str, second: str) -> None

        Exchange the names of the entries ``first`` and ``second``.

        Only the entry table changes, as for ``rename``. Afterwards ``first`` names what ``second``
        held and the other way round, which is the step a program that writes the next value of a
        tensor beside the current one takes to make the next value current. Swapping an entry with
        itself does nothing.

        :raises Exception: when either entry is missing, or the file is open for reading.


    .. py:method:: replace(source: str, target: str) -> None

        Make the entry ``source`` the entry ``target``, dropping what ``target`` held.

        Only the entry table changes, as for ``rename``, and in one commit: a crash leaves either
        both entries as they were or ``target`` holding what ``source`` held and no entry ``source``.
        The space ``target's`` old elements took is free from that commit on. This is the step that
        makes a value written beside the current one current, leaving no second entry behind.
        Replacing an entry with itself does nothing.

        .. versionadded:: 2.0.0

        :raises Exception: when there is no entry ``source``, or the file is open for reading.
        :raises Exception: when no entry can hold the name ``target``.


    .. py:method:: replace_all(moves: list[tuple[str, str]]) -> None

        Make each entry ``source`` the entry ``target``, for every pair of ``moves`` at once.

        Every pair is applied as by the overload for one pair, and all of them
        in one commit: a crash leaves either every entry as it was or every replacement made. This is
        the step that makes the values written beside several current ones current together.

        .. versionadded:: 2.0.0

        :param moves: The (source, target) pairs. A pair whose source is its target does nothing.
        :raises Exception: when a source is missing, or the file is open for reading.
        :raises Exception: when no entry can hold a target's name, or a name is the source or the target of more than one pair, or both a source and a target, which would make the outcome depend on the order the pairs were applied in.


    .. py:method:: remove(name: str) -> None

        Remove the entry ``name``, for every rank that holds one, and commit.

        Its data region becomes space later entries reuse; ``compact`` gives it back to the disk.

        :raises Exception: when there is no entry ``name``, or the file is open for reading.


    .. py:method:: restage(name: str, order: list[int], buffer_bytes: int = 0) -> None

        Store the entry ``name`` with its axes in ``order``, moving its elements, and commit.

        The elements are copied into a new region in the new order through a buffer of at most
        ``buffer_bytes``, and one commit then points the entry at it, so the entry holds its old layout
        or its new one whenever the program stops. The file needs room for a second copy of the entry
        while this runs. Restaging to the order the entry already has does nothing.

        :param name: The entry.
        :param order: The declared axis to store at each position, as ``stored_order`` returns it.
        :param buffer_bytes: As for ``copy``.
        :raises Exception: when there is no entry ``name``, or the file is open for reading.
        :raises Exception: when ``order`` is not a permutation of the entry's axes.


    .. py:method:: compact(buffer_bytes: int = 0) -> None

        Rewrite the file without the space no entry uses.

        Every entry is copied, in its stored order and through a buffer of at most ``buffer_bytes``,
        into a new file beside this one, which then replaces it. The file is this one or the
        compacted one whenever the program stops, and the disk needs room for the entries' bytes
        while this runs. Another handle open on the file refuses to commit afterwards; backings,
        which open the file for each slab, see the compacted file at their next slab.

        :param buffer_bytes: As for ``copy``.
        :raises Exception: when the file is open for reading.

.. py:function:: copy_entry(src_path: str, src_entry: str, dst_path: str, dst_entry: str) -> None

    Copy the entry ``src_entry`` of ``src_path`` into the entry ``dst_entry`` of ``dst_path``.

    The destination file is created when it does not exist, and the destination entry, with the
    source's extents, element type and stored order, when it does not exist. An existing one must
    have the same extents and element type. The elements pass through a buffer of at most
    ``--einsums:work-buffer-size``, so neither entry is held whole. See ``TensorFile::copy``.

    .. versionadded:: 2.0.0

    :param src_path: The file holding the entry to copy.
    :param src_entry: The entry to copy.
    :param dst_path: The file to copy it into, which may be ``src_path``.
    :param dst_entry: The entry to copy it into.
    :raises Exception: when the source file or entry is missing.
    :raises Exception: when the destination entry exists with other extents or another element type.


.. py:function:: etn_backing(path: str, entry: str, write: bool = False, order: list[int] = std::vector<std::size_t>{}, update: bool = False) -> TensorBacking

    The backing for one entry of a ``.etn`` file.

    Each read or write opens the file, checks that the entry still has the extents and element
    type it had when the backing was built, and moves the slab: a file rewritten between replays
    is used afresh, and one rewritten with a different shape is refused rather than read or
    written as the wrong elements.

    .. code-block:: text

       auto &B = graph.declare_runtime_tensor<double>("B_vv", {naux, nvir, nvir});
       graph.annotate_backing(B, tensor_io::etn_backing("ints.etn", "B_vv"));         // an input
       auto &T = graph.declare_runtime_tensor<double>("T2", {nocc, nocc, nvir, nvir});
       graph.annotate_backing(T, tensor_io::etn_backing("amps.etn", "T2", true));     // produced and stored

    .. versionadded:: 2.0.0

    :param path: The file. Stored as given: a relative path is resolved against the working directory each time the graph reads or writes it, and again when a saved graph is loaded.
    :param entry: The entry's name within the file.
    :param write: False (the default) for an input the graph reads: the entry must exist, and its extents and element type are read from it now. True for a tensor the graph produces and stores: the file and entry are created, or reused when the entry already holds a tensor of the same shape and type, when the backing is annotated on its tensor, which supplies that shape and type.
    :param order: For a write backing, the order to store a new entry's axes in: the declared axis at each stored position (see ``TensorEntry::stored_order``). Empty, the default, leaves it to the graph, which stores a new entry so the boxes it moves are long contiguous runs of the file. Give it when another run will read the entry in boxes of its own. An entry that already exists has to be stored in this order to be reused.
    :param update: True for a tensor the graph both reads and writes, whose entry it updates at every replay: the entry must exist, and its extents and element type are read from it now. The tensor starts each replay holding what the entry holds, its writes go to the scratch entry ``<entry>.next``, and at the end of the replay that entry replaces ``entry`` in one commit, so the file holds the previous replay's value until then. Not with ``write`` or ``order``.
    :returns: The backing, for ``compute_graph::Graph::annotate_backing``.
    :raises Exception: when a read backing's file cannot be opened or holds no such entry.
    :raises Exception: when a read backing's entry holds integers, which no graph tensor does, or, at annotation, when a write backing's entry already holds another shape or type, or is stored in another order than ``order`` asks for; or when ``update`` is given with ``write`` or ``order``, or ``entry`` is too long to name its scratch entry.

.. py:function:: swap_entries(path: str, first: str, second: str) -> None

    Exchange the names of the entries ``first`` and ``second`` of ``path``.

    Only the file's entry table changes. A program that reads one entry and writes the next value
    beside it swaps the two after each step, so the same entry always holds the current value and
    one graph serves every step. See ``TensorFile::swap``.

    .. versionadded:: 2.0.0

    :raises Exception: when the file or either entry is missing.

    Write a tensor to a .etn file, graph-aware.

    During graph capture, records a DiskWrite node that executes after the
    tensor is computed. Outside capture, writes immediately.

    Write a slab of a tensor to a .etn file, graph-aware.
