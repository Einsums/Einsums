.. py:class:: IndexSpace

    A per-irrep selection of indices along one axis of a tiled tensor.

    Each axis of a ``TiledRuntimeTensor`` is partitioned into per-irrep blocks.
    An IndexSpace picks a half-open ``[start, stop)`` sub-range out of each
    irrep's block, so a single IndexSpace can describe e.g. "the occupied
    orbitals" (``[0, nocc_h)`` in every irrep ``h``) or "the virtuals"
    (``[nocc_h, nmo_h)``). Slicing a tiled tensor with one IndexSpace per axis
    (``A.view({o, v, o, v})``) yields a ``TiledRuntimeTensorView``.

    .. versionadded:: 2.0.0


    .. py:method:: __init__(r: list[tuple[int, int]]) -> None

        Build from explicit per-irrep ``(start, stop)`` ranges.


    .. py:method:: nirrep() -> int

        Number of irreps this space covers.


    .. py:method:: start(h: int) -> int

        First index selected in irrep ``h``.


    .. py:method:: stop(h: int) -> int

        One past the last index selected in irrep ``h``.


    .. py:method:: length(h: int) -> int

        Number of indices selected in irrep ``h``.



.. py:class:: MemoryPool

    A pre-reserved region of memory that mimalloc manages exclusively.

    An exclusive mimalloc arena plus a heap bound to it. A carve takes about a microsecond for a
    multi-megabyte block, against tens to hundreds for an mmap, and a free returns the bytes at once.
    When the arena runs out the pool reserves another and warns, rather than throwing in a kernel.

    ``allocate`` must run on the constructing thread (it throws otherwise); freeing may happen on any.
    Arenas are capped per process and never returned to the OS, so keep pools few, long-lived and
    reserved to their peak size up front.

    .. versionadded:: 2.0.0


    .. py:method:: __init__(reserve_bytes: int, name: str = "pool", warn_bytes: int = 0, pinned: bool = False) -> None

        Reserve a pool.

        .. versionadded:: 2.0.0

        :param reserve_bytes: Bytes the caller expects to carve; the arena adds headroom.
        :param name: Label used in log messages.
        :param warn_bytes: Usage that logs a one-shot warning; zero disables it.
        :param pinned: Keep freed pages resident, so recarves are fault-free but the pool never shrinks below its high water. For small, hot scratch pools only; unpinned pages purge back to the OS.
        :raises Exception: if the arena cannot be reserved.


    .. py:method:: reserve(bytes: int) -> None

        Grow the pool so at least ``bytes`` of capacity are reserved.

        A no-op when already that large. Reserve once rather than in steps: each growth costs an
        arena, and arenas are capped and never reclaimed.

        .. versionadded:: 2.0.0


    .. py:method:: reset() -> None

        Bulk-free everything the pool holds and start over.

        .. versionadded:: 2.0.0

        :raises Exception: if any keepalive token is outstanding, or if an epoch is open.

.. py:class:: MemoryPoolEpoch

    RAII scope whose carves are released together when it closes.

    Each epoch gets a heap of its own inside the pool's arena, so closing it
    bulk-frees every carve made inside it, including ones nothing tracked.
    Epochs nest and must close in reverse order of opening.

    If a keepalive token carved in the scope is still held, ``close`` throws (Python's ``with`` takes
    this path), while the destructor logs an error and moves the surviving blocks to the pool's base
    heap, where they stay valid until their tokens die.

    .. versionadded:: 2.0.0


    .. py:method:: close() -> None

        Close the scope, releasing everything carved inside it.

        .. versionadded:: 2.0.0

        :raises Exception: if a keepalive token from this scope is still held, or if an inner epoch is still open.


    .. py:attribute:: open
        :type: bool

        True until ``close`` or the destructor runs.


        (read-only)

    Like GeneralRuntimeTensor, this kind of view is unable to be used in many of the same ways as a tensor with compile-time rank, and is
    mostly used for communication with the Python interface. To use it with rank-templated Einsums calls, convert it into a TensorView so
    that the rank can be coerced at compile time.

.. py:class:: SymmetryDescriptor

    Describes the symmetry of a tensor as a set of generators.

    The group is the generators' closure; only the generators are stored (ERIs need three).

    **Common patterns**

    - ``SymmetryDescriptor::symmetric_pair(i, j)``: ``T(..,i,..,j,..) = T(..,j,..,i,..)``.
    - ``SymmetryDescriptor::antisymmetric_pair(i, j)``: negated on swap.
    - ``SymmetryDescriptor::hermitian_pair(i, j)``: symmetric plus complex conjugate.
    - ``SymmetryDescriptor::eri_8fold()``: 8-fold ERI symmetry in chemists' notation.
    - ``SymmetryDescriptor::ccsd_t2()``: antisym in (0,1) and antisym in (2,3).

    **Tolerance**

    Floating-point arithmetic drifts away from exact symmetry. ``tolerance``
    is the maximum absolute element-wise deviation that ``check_symmetry()``
    accepts as "still symmetric."


    .. py:method:: __init__() -> None
                   __init__(gens: list[SymmetryOp], tol: float = 9.9999999999999998E-13) -> None

        A descriptor from its generators, and the deviation ``tolerance`` accepts.


    .. py:method:: empty() -> bool

        Whether there are no generators, which describes no symmetry.


    .. py:method:: size() -> int

        How many generators there are.


    .. py:staticmethod:: symmetric_pair(a: int, b: int) -> SymmetryDescriptor

        Symmetric in a single index pair: ``T(..,a,..,b,..) = T(..,b,..,a,..)``.


    .. py:staticmethod:: antisymmetric_pair(a: int, b: int) -> SymmetryDescriptor

        Antisymmetric in a single index pair: ``T(..,a,..,b,..) = -T(..,b,..,a,..)``.


    .. py:staticmethod:: hermitian_pair(a: int, b: int) -> SymmetryDescriptor

        Hermitian in a single index pair (complex tensors):
        ``T(..,a,..,b,..) = conj(T(..,b,..,a,..))``.


    .. py:staticmethod:: anti_hermitian_pair(a: int, b: int) -> SymmetryDescriptor

        Anti-Hermitian / skew-Hermitian: ``T(..,a,..,b,..) = -conj(T(..,b,..,a,..))``.


    .. py:staticmethod:: eri_8fold() -> SymmetryDescriptor

        8-fold symmetry of real two-electron integrals in chemists' notation
        ``(μν|λσ) = (νμ|λσ) = (μν|σλ) = (νμ|σλ) = (λσ|μν) = (σλ|μν) = (λσ|νμ) = (σλ|νμ)``.
        The three generators are: swap(0,1), swap(2,3), group_swap({0,1},{2,3}).


    .. py:staticmethod:: eri_4fold() -> SymmetryDescriptor

        4-fold symmetry of complex two-electron integrals: two real-pair swaps,
        no bra/ket swap (which would also complex-conjugate).


    .. py:staticmethod:: ccsd_t2() -> SymmetryDescriptor

        CCSD T2 amplitudes ``T[a,b,i,j]``: antisym in virtual pair (0,1) and
        antisym in occupied pair (2,3), so ``T[a,b,i,j] = -T[b,a,i,j] =
        -T[a,b,j,i] = T[b,a,j,i]``.



.. py:class:: SymmetryOp

    One generator of a tensor's symmetry group.

    ``permutation[i]`` is the new position of the index that currently sits at
    position ``i``. For a tensor ``T(i0, i1, ...)`` the operation maps
    ``T(i0, i1, ...) -> sign * T(i_{perm[0]}, i_{perm[1]}, ...)``. For the
    Hermitian case the right-hand side is additionally complex-conjugated.

    Padding: for tensors of rank < ``kMaxSymmetryRank`` the unused trailing
    positions must be filled with their natural index (``permutation[i] = i``).


    .. py:staticmethod:: identity() -> SymmetryOp

        Identity operation: all positions map to themselves.


    .. py:staticmethod:: swap(a: int, b: int, sign: int = +1, conjugate: bool = False) -> SymmetryOp

        Swap two index positions. All other positions are identity.


    .. py:staticmethod:: group_swap(g1: list[int], g2: list[int], sign: int = +1, conjugate: bool = False) -> SymmetryOp

        Swap two index groups, held in vectors, which is the form a binding can pass.
        ``SymmetryOp.group_swap([0, 2], [1, 3])`` on ``T[i, j, a, b]`` exchanges the pair ``(i, a)``
        with the pair ``(j, b)``.



.. py:class:: TiledRuntimeTensorF

    A runtime-rank, tile-wise sparse tensor.

    This is the runtime-rank analogue of ``TiledTensor``. Where ``TiledTensor``
    carries its rank as a compile-time template parameter (and therefore keys its
    tiles by ``std::array<int, Rank>``), TiledRuntimeTensor stores its rank at
    runtime and keys tiles by ``std::vector<int>``. Each populated tile is a dense
    ``RuntimeTensor`` (which reuses ``detail::TensorImpl`` for its runtime-rank
    dims/strides machinery); absent tiles are rigorously zero and are not stored.

    Like ``TiledTensor`` this models a *general* tiled layout: a tile may sit
    anywhere on the grid (not only the diagonal) and may be rectangular. The
    block-diagonal, square-tile special case is what ``BlockTensor`` captures;
    the off-diagonal / rectangular cases (e.g. a non-totally-symmetric operator
    coupling different symmetry sectors) require this general form.

    **ComputeGraph integration (Tier A)**

    This type satisfies ``CoreBasicTensorConcept`` so it can be captured into a
    ComputeGraph for *lifecycle orchestration* (materialize / release / zero) and
    passed around as an operand handle. Because a multi-tile tensor has no single
    contiguous backing buffer, ``data()`` returns ``nullptr`` for the multi-tile
    case (and the single tile's pointer in the degenerate one-cell grid), and the
    type advertises itself via ``is_tiled_tensor()`` so the graph can flag the
    handle (``TensorHandle::is_tiled``) and keep it out of dense buffer-level code
    paths. Tiled *contraction inside the graph* is intentionally not provided here.

    .. versionadded:: 2.0.0


    .. py:method:: __init__(name: str, tile_sizes: list[list[int]]) -> None

    .. py:method:: rank() -> int

        Runtime rank (number of grid axes).


    .. py:method:: dim(d: int) -> int

        Global extent along axis ``d`` (sum of that axis's tile sizes). Supports
        Python-style negative indexing.


    .. py:method:: dims() -> list[int]

        Global shape (one extent per axis).


    .. py:method:: grid_size() -> int

        Number of grid cells (product of the per-axis tile counts). This is the
        number of *possible* tiles, not the number populated.


    .. py:method:: num_filled_tiles() -> int

        Number of populated (non-zero) tiles.


    .. py:method:: tile_sizes() -> list[list[int]]

        The per-axis tile sizes (the grid).


    .. py:method:: tile_offsets() -> list[list[int]]

        The per-axis tile offsets (running sums of the tile sizes).


    .. py:method:: has_tile(coord: list[int]) -> bool

        True if a tile exists at the given grid coordinate.


    .. py:method:: add_tile(coord: list[int]) -> None

        Declare a tile at ``coord``. The declaration is deferred, with no storage allocated.

        Creates a shell ``RuntimeTensor`` with the right dims for that grid cell
        but no backing data. The tile is allocated later by ``materialize`` (or
        by the ComputeGraph MaterializationPass). No-op if the tile already
        exists.

        :param coord: The grid coordinate, one index per axis.


    .. py:method:: tile_view(coord: list[int]) -> RuntimeTensorView

        Python-facing tile accessor: materialize the tile at ``coord`` (creating
        it if absent) and return a numpy-backed view of it. KEEP_ALIVE(0,1) ties
        this tensor's lifetime to the returned view, so the tile's storage
        outlives any numpy array Python builds from it.


    .. py:method:: view(spaces: list[IndexSpace]) -> TiledRuntimeTensorView

        Create a non-owning ``TiledRuntimeTensorView`` restricted to one
        ``IndexSpace`` per axis (e.g. ``A.view({o, v, o, v})``). The view keeps
        this tensor alive; defined out-of-line below TiledRuntimeTensorView.


    .. py:method:: materialize() -> None

        Allocate backing storage for every populated tile. Idempotent.


    .. py:method:: release() -> None

        Release backing storage for every populated tile, returning to the
        deferred state. The sparsity pattern (which tiles exist) is preserved.


    .. py:method:: zero() -> None

        Zero every populated tile.


    .. py:method:: set_all(val: Any) -> None

        Set every element of every populated tile to ``val``.


    .. py:attribute:: name
        :type: str

.. py:class:: TiledRuntimeTensorViewF

    A non-owning, per-irrep-sliced view of a ``TiledRuntimeTensor``.

    Produced by ``TiledRuntimeTensor::view`` with one ``IndexSpace`` per axis.
    It does not own data: each populated tile is exposed as a
    ``RuntimeTensorView`` sub-block of the parent tile (via
    ``RuntimeTensor::at_view``), so a view like ``A[o, v, o, v]`` over an MO
    tensor selects the occ/vir sub-blocks of every symmetry-allowed tile with no
    copies. The parent must outlive the view.

    .. versionadded:: 2.0.0

    .. py:method:: dims() -> list[int]

    .. py:method:: dim(d: int) -> int

    .. py:method:: tile_sizes() -> list[list[int]]

        Per-axis, per-irrep sizes of the selected sub-blocks.


    .. py:method:: has_tile(coord: list[int]) -> bool

        The view shares the parent's sparsity pattern (same populated coords).


    .. py:method:: num_filled_tiles() -> int

    .. py:method:: tile_view(coord: list[int]) -> RuntimeTensorView

        Sub-view of the parent's tile at ``coord``, restricted to this view's
        per-axis ranges for that tile's irreps. The result is a live
        ``RuntimeTensorView`` onto the parent tile's storage.


    .. py:attribute:: name
        :type: str

        (read-only)

.. py:function:: einsum(spec: str, C: Any, A: Any, B: Any, c_pf: Any = typename CType::ValueType{0}, ab_pf: Any = typename AType::ValueType{1}, conj_a: bool = False, conj_b: bool = False) -> None

    Graph-aware einsum: contract A and B according to ``spec``.

    ``spec`` is a string of the form ``"<output> <- <a> ; <b>"``; e.g.
    ``"ij <- ik ; kj"`` (matrix multiply), ``"i <- ij ; j"`` (matrix-
    vector), ``" <- i ; i"`` (dot product). ``c_pf`` and ``ab_pf``
    default to 0 and 1, giving ``C = A op B``, but can be set to
    accumulate (``c_pf=1``) or scale.

    Complex prefactors are fully supported for complex dtypes:
    the einsum node's live params and its descriptor store PrefactorScalar (a
    variant covering float/double/complex<float>/complex<double>), so a
    complex ``c_pf``/``ab_pf`` round-trips through capture and replay
    without narrowing.

    ``conj_a`` / ``conj_b`` conjugate A / B inside the contraction for complex
    dtypes, and are a no-op for real. They conjugate only the elements. A
    conjugate-transpose is the conj flag combined with transposed index placement
    in the spec, just like any transpose in einsum. To compute ``C = A^H @ B``,
    store A as ``(k, i)`` so its row index k is the one contracted:

    .. code-block:: text

       // (A^H @ B)[i,j] = sum_k conj(A[k,i]) * B[k,j]
       einsum("ij <- ki ; kj", C, A, B, conj_a=True);   // A^H @ B
       einsum("ij <- ik ; jk", C, A, B, conj_b=True);   // A @ B^H
       einsum("ij <- ik ; kj", C, A, B, conj_a=True);   // conj(A) @ B  (no transpose)

    Equivalently, wrap an operand in ``conj(...)`` directly in the spec; it ORs
    with the kwargs, so ``einsum("ij <- conj(ki) ; kj", C, A, B)`` is also A^H @ B.
    Native for GEMM-shaped contractions via PackedGemm, with no operand copy. The
    generic loop conjugates per element otherwise. Not supported for tiled operands.

.. py:function:: permute(spec: str, C: Any, A: Any, c_pf: Any = typename CType::ValueType{0}, a_pf: Any = typename AType::ValueType{1}) -> None

    Graph-aware permute with explicit prefactors.

    ``spec`` is a permutation pattern such as ``"ji <- ij"`` (transpose)
    or ``"kji <- ijk"`` (rank-3 reorder). Computes
    ``C = c_pf * C + a_pf * permute(A)`` according to ``spec``. ``c_pf`` defaults to 0 and
    ``a_pf`` to 1, i.e. ``C = permute(A)``.

.. py:function:: set_log_level(level: int) -> None

    Set the runtime log level on the einsums logger.

    Values mirror spdlog: 0=TRACE, 1=DEBUG, 2=INFO, 3=WARN, 4=ERROR, 5=CRITICAL, 6=OFF.
    Out-of-range values are clamped by spdlog. Compile-time disablement via
    ``EINSUMS_ACTIVE_LOG_LEVEL`` takes precedence, so a runtime
    ``set_log_level(0)`` cannot re-enable TRACE in a Release build.

.. py:class:: OptLevel

    Optimization level for Graph::optimize(), compiler-style.

    - O0: no passes; the graph runs exactly as captured.
    - O1: node-count cleanup only (constant folding, dead-scale removal, permute fusion, CSE, dead-node elimination, elementwise fusion) - cheap, no restructuring, no memory planning.
    - O2: the full default pipeline (cleanup + loop hoisting + cost-model chain restructuring + batching + reorder + distribution/GPU when available + in-place merging + free insertion + the memory arena).
