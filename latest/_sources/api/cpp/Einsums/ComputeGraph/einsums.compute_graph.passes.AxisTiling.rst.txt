einsums::compute_graph::passes::AxisTiling
==========================================

.. note::

.. cpp:namespace:: einsums::compute_graph::passes

.. cpp:class:: AxisTiling : public OptimizerPass

   Rewrite a program as a loop over slices of its free axes, under a memory cap.

   .. code-block:: text

      cg::PassManager manager;
        auto tiling = std::make_shared<cg::passes::AxisTiling>();
        tiling->set_memory_cap(4096);
        manager.add(tiling);
        graph.apply(manager);

   A member of ``PassManager::create_default``, after the algebraic rewrites. By default the cap
   is what the ``--einsums:max-memory`` option leaves after every other tensor of the graph, so in the default
   pipeline the pass streams only a program that would not fit; on one that fits it does no more
   than run a provably symmetric region as a triangle where that is cheaper. A caller with a smaller footprint to live inside sets a cap of
   its own.

   .. versionadded:: 2.0.0


   .. cpp:function:: AxisTiling() = default

      Default-construct, reading the cap from ``option::GraphTilingMemoryCap``.


   .. cpp:function:: explicit AxisTiling(CostModel cost_model)

      Price triangles against ``cost_model`` instead of the detected machine's.

      populate_default() passes the profile it shares with the other cost-model passes, so every
      planning decision is made against one machine.

   .. cpp:function:: std::optional<NodeFeatures> understood_features() const override

   .. cpp:function:: bool recurse_into_subgraphs() const override

      See ``OptimizerPass::recurse_into_subgraphs``.

      A loop body is where an iterative method keeps the work worth tiling: a coupled-cluster
      residual lives in the body of its DIIS loop. A region never crosses out of the graph it was
      found in, so the loop the rewrite emits nests inside the body, and a loop this pass emitted
      is not visited again in the same apply.


   .. cpp:function:: PassTier tier() const override

      See ``OptimizerPass::tier``.

      The per-slice algebra is bitwise the captured algebra. The reduction that becomes an
      accumulation across iterations is not, because a sum split into per-slice partial sums
      adds them in a different order.

   .. cpp:function:: void set_block_extent(std::int64_t extent)

      Pin the block extent of a triangle's two axes.

      A triangle's block is priced from the machine's measured kernel rates, so the block it
      chooses moves between machines. A test that checks the emission at a given block pins it
      here. A pinned block that does not fit the memory the region may take declines the triangle.

      .. versionadded:: 2.0.0

      :param extent: The block, two or more; zero lets the cost model choose, which is the default.


   .. cpp:function:: void use_reference_cost_model()

      Price against the cost model's built-in rates instead of the detected machine's.

      The pass prices each candidate from the machine's measured kernel rates, so where two
      candidates are close the one it chooses moves between machines. With the built-in rates the
      decision is the same on every machine, which is what a test that checks the choice needs.

      .. versionadded:: 2.0.0

   .. cpp:class:: Footprint

      The memory one region may take. What the tree's tensors hold, and when.

      An intermediate of the graph being tiled is held from its first writer to its last reader,
      in the graph's current order, since the memory passes allocate it before the one and free
      it after the other. Everything else is counted as held throughout: the caller's tensors,
      an intermediate read before it is written, and the tensors of the tree's other graphs,
      whose order this pass does not follow.
