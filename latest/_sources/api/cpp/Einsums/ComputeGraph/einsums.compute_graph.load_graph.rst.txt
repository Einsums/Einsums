einsums::compute_graph::load_graph

.. cpp:function:: expected<Graph, GraphError> load_graph(const std::string &path)

   Read an ``einsums_graph_ir`` file back as a runnable graph.

   The graph comes back with every node's executor rebuilt through
   ``build_executor``, its alias relation derived structurally
   (``Graph::link_alias_structural``, reached through
   ``Graph::link_alias_storage`` since a loaded graph has no addresses), and its
   manifest intact, so ``Graph::bind`` works by name immediately. Placeholder
   storage is allocated for every slot so an unbound graph still executes rather
   than dereferencing nothing.

   The resource and tuning pass phases are NOT run; see the file note.

   .. versionadded:: 2.0.0

   :param path: The file to read.
   :returns: The graph, or the first reason it could not be built.


.. cpp:function:: expected<Graph, GraphError> load_graph(const std::string &path, SpaceRegistry &registry)

   Read ``path`` back, resolving its index spaces against ``registry``.

   A saved graph carries space NAMES rather than ids, because a ``SpaceId`` is meaningless
   outside the registry that issued it. Resolving them needs a registry, and the no-registry
   overload uses the process-global one, which is right for a program with one set of spaces and
   wrong for a caller who keeps their own: such a caller got "index space 'occ' is not registered
   in this process" with an empty list of what IS registered, having registered everything.

   The loaded graph is also told to USE ``registry``, so its annotations, a later save, and any
   pass that reads a space all agree with the ids it was built from.

   .. versionadded:: 2.0.0

   :param path: The file to read.
   :param registry: The registry the file's space NAMES are looked up in. Must outlive the graph.
   :returns: The graph, or the failure.
