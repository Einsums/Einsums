==================================
einsums::compute_graph::SetupState
==================================

.. note::
   Generated from the C++ headers by ``apiary --emit-cpp-docs-json``.

Defined in header ``Einsums/ComputeGraph/Node.hpp``.

.. cpp:namespace:: einsums::compute_graph

.. cpp:class:: SetupState

   Live state a ``SetupDescriptor`` shares with its executor.

   Held in a shared block for the reason ``LoopState`` states: an executor cannot hold a
   pointer into the node vector that passes insert into and reorder.

   The two keys are what makes the setup body skippable across a re-bind rather than only
   across a replay. ``pending_key`` is what the CALLER says the current problem is, written
   by ``Graph::set_setup_key``; ``computed_key`` is the problem the body last actually ran
   for. A bind clears ``computed``, and the executor then reruns unless the two keys agree
   and are non-empty, which is the caller stating that this is the same problem and the
   factors on hand are still its factors.

   An empty ``pending_key`` disables the cache, which is the default: refitting is always
   correct, and a graph whose caller has said nothing about problem identity gets the
   behavior that cannot be wrong.


   .. cpp:member:: bool computed

      Whether the body has run since the last ``Graph::invalidate_setup``.


   .. cpp:member:: std::string computed_key

      The problem the body last ran for, or empty when it has never run or ran with no key.


   .. cpp:member:: std::string pending_key

      The problem the caller says is bound now, or empty when the caller has not said.
