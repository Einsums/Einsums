einsums::compute_graph::OperandAccessor

.. cpp:namespace:: einsums::compute_graph

.. cpp:class:: OperandAccessor

   One operand's live geometry, resolved once when an executor is built.

   Resolution order is slot first, handle second, and the order is the point.
   A ``TensorSlot`` is what ``Graph::rebind`` and ``Graph::redirect_slot``
   repoint, so reading through it is what makes a built executor honor both
   without the pass author having to think about it. ``TensorHandle::impl_fn``
   is the fallback for a tensor that reached the graph without ever being
   captured through a slot, which is only ever a node some pass assembled.

   Neither path allocates or looks anything up at call time: the slot address
   is stable for the graph's lifetime, and ``TensorSlot::impl_of`` is a plain
   function pointer.

   .. seealso::

      resolve_operand

      The operand's element type, recorded from its tensor when the accessor was resolved; Unknown

      The operand's CURRENT rank-erased geometry, type-erased.


   .. cpp:function:: template <typename T> detail::TensorImpl<T> * impl() const

      The operand's CURRENT rank-erased geometry, as element type ``T``.

      :throws std::logic_error: when the operand's recorded type is not ``T``. The cast below would otherwise reinterpret the tensor's memory as another type and compute garbage, silently: an executor built with the wrong type, by a pass or anything else, fails here instead.
