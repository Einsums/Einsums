=======================================
einsums::compute_graph::passes::Reorder
=======================================

.. note::
   Generated from the C++ headers by ``apiary --emit-cpp-docs-json``.

Defined in header ``Einsums/ComputeGraph/Passes/Reorder.hpp``.

.. cpp:namespace:: einsums::compute_graph::passes

.. cpp:class:: Reorder : public OptimizerPass

   Memory-aware topological sort: reschedules independent nodes so the ones that free the most memory run earliest.

   Re-sorts the node list with a priority-based Kahn's algorithm. The dependency graph encodes all three hazard classes -- RAW
   (writer->reader), WAW (writer->writer), and WAR (reader->writer) -- over each node's *effective* I/O (so a Loop/Conditional
   carries edges for the tensors its body touches) with view aliases resolved to the owning buffer, so only genuinely independent
   nodes may swap. Among the ready set, a max-heap picks the node with the highest net score: the bytes of the tensors it is the
   last user of, less the bytes of those it is the first user of, counting only tensors the graph frees (intermediates and
   graph-owned read-backed tensors). Equal scores keep program order. The reschedule is kept only if its peak, with each such
   tensor live from its first use to its last, is lower than the given order's. The pass moves nodes only; it never adds,
   removes, or rewrites them.

   In the default pipeline (populate_default, after GEMMBatching so the scheduler sees a batched node as one unit). Not in the
   O1 cleanup cluster of PassManager::create_for.

   **Example (C++)**

   .. code-block:: text

      cg::Graph graph("reorder");
      {
          cg::CaptureGuard const capture(graph);
          cg::einsum("ij <- ik ; kj", 0.0, &Big, 1.0, A, B);   // large intermediate
          cg::einsum("pq <- pr ; rq", 0.0, &Small, 1.0, X, Y); // independent, small
          cg::einsum("i <- ij", 0.0, &r, 1.0, Big);            // last consumer of Big -> frees it
      }
      cg::PassManager pm; pm.add<cg::passes::Reorder>();
      graph.apply(pm);                                          // or PassManager::create_default()
      // Among ready nodes the reducer over Big is scheduled early so Big is freed before Small's chain grows the footprint.

   **Example (Python)**

   .. code-block:: py

      import einsums, einsums.graph as cg
      g = cg.Graph("reorder")
      with cg.capture(g):
          einsums.einsum("ij <- ik ; kj", Big, A, B)
          einsums.einsum("pq <- pr ; rq", Small, X, Y)
          einsums.einsum("i <- ij", r, Big)
      pm = cg.PassManager(); pm.add(cg.Reorder())
      g.apply(pm)                                              # or cg.default_pass_manager()
      # Reorder exposes no result counter; it only permutes the node order to lower peak memory.

   **Limitations**

   - It **reschedules only**: it never fuses, splits, or eliminates nodes, and it cannot lower peak memory below what the fixed node set and its true dependencies allow.
   - The net-score ranking is a **greedy local heuristic**, not a globally optimal peak-memory schedule. The peak check only guarantees it is never worse than the order given.
   - The peak it compares is a model: it ignores FreeInsertion's size floor, so a tensor below it counts as freed here but stays allocated at run time.
   - If the dependency graph is cyclic or otherwise leaves nodes unscheduled (`order.size() != n`), the pass bails and leaves the node order untouched.
   - Tensor sizes come from `TensorHandle::total_bytes()`; the pass runs before Materialization, so sizes are taken from declared dims rather than realized allocations.

   **Future improvements**

   - Replace the greedy last-consumer heuristic with a cost-model-driven schedule that minimizes true peak footprint (e.g. lookahead or a liveness-interval formulation) instead of a per-step local choice.
