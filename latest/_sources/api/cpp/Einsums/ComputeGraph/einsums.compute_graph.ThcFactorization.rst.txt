   .. cpp:function:: static std::shared_ptr<ThcFactorization> for_amplitude(std::string tag, RuntimeTensorView<double> amplitude, std::vector<RuntimeTensorView<double>> collocations, double bound, double drop_threshold, std::string name)

      Fit the TAGGED tensor itself, for an amplitude a solver rewrites every iteration.

      **Why this is a different provider rather than a different tag**

      A density fit reads a three-index tensor the caller handed over and merely CLAIMS it
      approximates the tagged four-index one; the factors are the same however often that tensor
      moves. This one projects the tagged tensor onto the grid basis,
      :math:`Z = S^{-1} (X^T T X) S^{-1}`, so the factors are a function of the tensor and are
      re-fitted wherever it is written. That is what ``FactorizationPlan::fits_from_tagged`` says,
      and it is what lets a tensor a loop body updates be factorized at all.

      **The residual is measured without forming the fit**

      :math:`\lVert T - \tilde{T}\rVert^2 = \lVert T\rVert^2 - 2\langle Z, P\rangle + \langle Z, S Z S\rangle` with :math:`P = X^T T X`, every term of which is a grid-sized
      contraction the fit already computes or a dot of the tagged tensor with itself. So the
      accuracy statement is a real measurement here, where the integral fit's is an assertion,
      and the record names the tensor it lands in.

      :param tag: The provenance tag this claims, e.g. ``"amplitude"``.
      :param amplitude: The very tensor the caller tags. Checked against the tagged handle's buffer in ``propose``, so a caller who hands over a different tensor gets a decline rather than a fit of something else.
      :param collocations: One matrix per axis, or one for every axis.
      :param bound: The relative error asserted, or zero to take ``einsums:graph:thc-epsilon``.
      :param drop_threshold: See ``default_drop_threshold``.
      :param name: The provider's name.
      :returns: The provider.

   .. cpp:function:: static std::shared_ptr<ThcFactorization> for_three_index(std::string tag, RuntimeTensorView<double> three_index, std::vector<RuntimeTensorView<double>> collocations, double bound, double drop_threshold, std::string name)

      Fit the three-index tensor of a density fit, rather than the four-index tensor.

      **Why the three-index tensor rather than the four-index one**

      A density-fitted program never forms :math:`(ab|ef)`, so a provider that only claims a
      rank-4 tensor has nothing to offer it: what the program holds is ``B`` and what it writes
      is a chain over the auxiliary index. The fit is the one the four-index fit already
      computes on its way to ``Z``, stopped one step earlier,

      .. math::

         B[A,m,n] \approx \sum_P C[A,P]\,X_0[m,P]\,X_1[n,P],
             \qquad C = \tilde{B} S^{-1}

      so it is three factors over one grid letter where the four-index form is five over two.
      It is also the smaller object: ``C`` is auxiliary-by-grid where ``Z`` is grid-by-grid, and
      the two occurrences of ``B`` in a ladder term get one fitting between them.

      **Its accuracy statement is measured**

      The exact quantity is the tagged tensor and the fit reads it, so the residual is a number
      rather than a claim, exactly as it is for an amplitude fit. That is also what
      ``FactorizationPlan::fits_from_tagged`` says of it.

      :param tag: The provenance tag this claims, e.g. ``"eri"``.
      :param three_index: ``B[A,m,n]``, which is also the tensor the caller tags. Checked against the tagged handle's buffer in ``propose``.
      :param collocations: One matrix per BASIS axis, so two for a rank-3 tensor, or one for both. Axis 0 is the auxiliary axis and has no collocation.
      :param bound: The relative error asserted, or zero to take ``einsums:graph:thc-epsilon``.
      :param drop_threshold: See ``default_drop_threshold``.
      :param name: The provider's name.
      :returns: The provider.

   .. cpp:function:: void report_residual_into(RuntimeTensorView<double> residual, RuntimeTensorView<double> reference)

      Where an amplitude fit writes what it was worth on this bind.

      The caller's own tensors, for the reason the energies of a Laplace transform are: a
      measurement a caller cannot read is a measurement nobody makes, and a value the graph
      declares for itself is one the graph keeps to itself. The record points at ``residual`` by
      name, so a caller holding a record knows which of their tensors to look in.

      Without this an amplitude fit emits no measurement and its record asserts its bound, which
      is what the integral fit does in every case.

      :param residual: A rank-1 tensor the fit writes :math:`\lVert T - \tilde{T}\rVert^2` into.
      :param reference: A rank-1 tensor the fit writes :math:`\lVert T\rVert^2` into.

   .. cpp:function:: static SpaceId register_grid_space(Graph &graph)

      Register the grid space in ``graph's`` own registry, if it is not there already.

      A space is a statement about a graph rather than about a provider, and ``propose`` is
      handed a const graph precisely so a provider cannot make one. So a caller registers it,
      and this is the one call that does: idempotent for a repeated identical declaration, as
      ``SpaceRegistry::register_space`` is.

      :param graph: The graph whose registry gains the space.
      :returns: The space's id in that registry.


   .. cpp:function:: static std::string residual_param_name(const std::string &provider, const std::string &tensor)

      The parameter the squared residual of the fit is reported under.

      Divided by ``reference_param_name`` and square-rooted, this is the RELATIVE least-squares
      residual of the grid fit against the three-index tensor it was fitted from. Per bind and

      :param provider: The provider's ``name``.

      :returns: The key to read out of the graph's parameter table after an execute.

   .. cpp:member:: static constexpr double default_drop_threshold

      The drop threshold a caller who states none gets.

      The same number ``MetricFitFactorization`` uses, and INHERITED rather than chosen for a
      grid: it is the magnitude a Coulomb metric's null space sits below, and a collocation
      metric has no null space to sit below. See the file note on why a caller with a real
      grid states a threshold of their own instead.
