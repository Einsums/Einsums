einsums::compute_graph::for_each_child_graph
============================================

.. note::
   Generated from the C++ headers by ``apiary --emit-cpp-docs-json``.

Defined in header ``Einsums/ComputeGraph/Node.hpp``.

.. cpp:namespace:: einsums::compute_graph

.. cpp:function:: template <typename NodeT, typename F> requires std::is_same_v<std::remove_cv_t<NodeT>, Node> void for_each_child_graph(NodeT &node, F &&visit, bool include_setup)

   Visit the graphs one node CONTAINS: a loop's body, a conditional's two branches, a setup's body.

   Which descriptors carry a sub-graph, and in what order, was written out at seven sites
   across three files. The order is part of the contract rather than a detail: the graph-IR
   writer interns a control-flow node's boundary tensors BY POSITION, so a walk that visited
   the else-branch first would place them in the dense order at indices nothing mentions them
   at. Empty bodies are skipped, so a visitor never sees a null graph.

   Visits one level. A visitor that wants the whole subtree recurses itself, which is what
   ``Graph::for_each_subgraph`` is: this over every node of a graph.

   :tparam NodeT: ``Node`` or ``Node const``; a const node hands the visitor ``Graph const &``.
   :tparam F: Invocable taking that graph reference.
   :param node: The node to look inside. A node holding any other descriptor has no child graph and is visited zero times.
   :param visit: Called once per child graph that exists.
   :param include_setup: False to skip a ``Setup`` body. For the one caller whose walk order has to agree with a component that descends into loops and conditionals only; see ``Graph::finish_replay_thread_plan``.
