einsums::compute_graph::LuPivots
================================

.. note::
   Generated from the C++ headers by ``apiary --emit-cpp-docs-json``.

Defined in header ``Einsums/ComputeGraph/LuPivots.hpp``.

.. cpp:namespace:: einsums::compute_graph

.. cpp:class:: LuPivots

   The row interchanges ``getrf`` produces, as something a graph can outlive.

   A pivot array is a list of BLAS integers, which is not one of the dtypes a tensor operand may carry, so it cannot be a graph
   TENSOR and cannot be a slot. It is instead a handle whose buffer is shared: ``getrf`` and ``getrs`` both bake a copy of the
   ``shared_ptr`` into their executors at capture time, so the buffer survives however long the graph does even if the handle the
   caller held is dropped first, and both see the same array on every replay.

   Because the pivots ride outside the dataflow, they carry no ordering of their own. What orders a factorization against its
   solves is the FACTORIZATION TENSOR: ``getrf`` writes it, ``getrs`` reads it, and the hazard scan serializes the pair on that
   edge. A ``getrs`` against a handle whose matching ``getrf`` writes a different tensor has nothing holding the two together
   and is a bug in the caller.

   The buffer is sized by ``getrf`` on the first execution and reused afterwards.


   .. cpp:function:: LuPivots()

      An empty pivot array. ``getrf`` sizes it to the order of the matrix it factors.


   .. cpp:function:: size_t size() const

      The number of interchanges recorded, which is zero until a ``getrf`` node has executed.


   .. cpp:function:: const std::shared_ptr<std::vector<blas::int_t>> & buffer() const

      The shared buffer, for an executor to bake in at capture time.
