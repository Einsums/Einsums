einsums::compute_graph::passes::LayoutAssignment
================================================

.. note::
   Generated from the C++ headers by ``apiary --emit-cpp-docs-json``.

Defined in header ``Einsums/ComputeGraph/Passes/LayoutAssignment.hpp``.

.. cpp:namespace:: einsums::compute_graph::passes

.. cpp:class:: LayoutAssignment : public OptimizerPass

   Choose the storage order of every graph-owned intermediate so contractions read flat.

   **Example (C++)**

   .. code-block:: text

      cg::Graph graph("layout");
      {
          cg::CaptureGuard const capture(graph);
          cg::einsum("mbej <- mnef ; njfb", 0.0, &W, 1.0, I, T);
          cg::einsum("ijab <- imae ; mbej", 1.0, &R, 1.0, T2, W);
      }
      cg::PassManager pm;
      pm.add<cg::passes::LayoutAssignment>();
      graph.apply(pm);   // W's axes are reordered and both index lists follow

   **Example (Python)**

   .. code-block:: py

      import einsums.graph as cg
      la = cg.LayoutAssignment()
      pm = cg.PassManager(); pm.add(la); pm.run(g)
      # la.num_relaid_out -> 1  (getters are properties, not methods)

   It also runs as part of ``cg.default_pass_manager()``.

   **Limitations**

   - Candidates are rank-3-and-up graph-owned deferred intermediates only; see the file note for why each half of that is there.
   - The search is coordinate descent over the layouts some participant asked for, not an exhaustive one over ``r``! orders per tensor. A layout nobody wants cannot beat one that at least one node does, which is what makes the restriction defensible rather than merely cheap; it is not a proof of optimality, and the pass does not claim one.
   - A ``Permute`` is folded away only when its copy is one of the decision variables above, which is where ``PermuteFusion`` still has cases of its own: a rank-two copy, a copy the caller owns, a copy already allocated, and a copy read by something other than a contraction are each pinned here and each still absorbed there. A ``Transpose`` carries no descriptor and is rank two by definition, so it is never a candidate.
   - The copy's source keeps its captured axes, so a chain of two permutes folds neither.
   - A contraction with a repeated letter in one operand (a diagonal) is not modelled, and pins its tensors.
