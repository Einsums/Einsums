===========================
einsums::TiledRuntimeTensor
===========================

.. note::
   Generated from the C++ headers by ``apiary --emit-cpp-docs-json``.

Defined in header ``Einsums/Tensor/TiledRuntimeTensor.hpp``.

.. cpp:namespace:: einsums

.. cpp:class:: template <typename T> TiledRuntimeTensor : public tensor_base::CoreTensor, public tensor_base::TiledTensorNoExtra, public design_pats::Lockable<std::recursive_mutex>

   A runtime-rank, tile-wise sparse tensor.

   This is the runtime-rank analogue of ``TiledTensor``. Where ``TiledTensor``
   carries its rank as a compile-time template parameter (and therefore keys its
   tiles by ``std::array<int, Rank>``), TiledRuntimeTensor stores its rank at
   runtime and keys tiles by ``std::vector<int>``. Each populated tile is a dense
   ``RuntimeTensor`` (which reuses ``detail::TensorImpl`` for its runtime-rank
   dims/strides machinery); absent tiles are rigorously zero and are not stored.

   Like ``TiledTensor`` this models a *general* tiled layout: a tile may sit
   anywhere on the grid (not only the diagonal) and may be rectangular. The
   block-diagonal, square-tile special case is what ``BlockTensor`` captures;
   the off-diagonal / rectangular cases (e.g. a non-totally-symmetric operator
   coupling different symmetry sectors) require this general form.

   **ComputeGraph integration (Tier A)**

   This type satisfies ``CoreBasicTensorConcept`` so it can be captured into a
   ComputeGraph for *lifecycle orchestration* (materialize / release / zero) and
   passed around as an operand handle. Because a multi-tile tensor has no single
   contiguous backing buffer, ``data()`` returns ``nullptr`` for the multi-tile
   case (and the single tile's pointer in the degenerate one-cell grid), and the
   type advertises itself via ``is_tiled_tensor()`` so the graph can flag the
   handle (``TensorHandle::is_tiled``) and keep it out of dense buffer-level code
   paths. Tiled *contraction inside the graph* is intentionally not provided here.

   .. versionadded:: 2.0.0

   :tparam T: The data type stored in each tile.

   .. cpp:function:: TiledRuntimeTensor(std::string name, std::vector<std::vector<int>> tile_sizes, bool row_major)

      Construct an empty tiled tensor from a tile grid.

      No tiles are populated yet; use ``add_tile`` / ``tile`` to declare the
      sparsity pattern. The grid is given as one vector of tile sizes per axis,
      so ``tile_sizes.size()`` determines the rank.

      :param name: The name of the tensor.
      :param tile_sizes: One vector per axis giving that axis's tile extents.
      :param row_major: Memory layout for the *global* shape metadata and for tiles created lazily. Defaults to the library setting.

      Raw data pointer.

      ``nullptr``. In the degenerate single-cell grid (one possible tile) it
      returns that tile's buffer if the tile exists, matching the dense case.
      See the class note on ComputeGraph integration.

   .. cpp:function:: void add_tile(const std::vector<int> &coord)

      Declare a tile at ``coord``. The declaration is deferred, with no storage allocated.

      Creates a shell ``RuntimeTensor`` with the right dims for that grid cell
      but no backing data. The tile is allocated later by ``materialize`` (or
      by the ComputeGraph MaterializationPass). No-op if the tile already
      exists.

      :param coord: The grid coordinate, one index per axis.
