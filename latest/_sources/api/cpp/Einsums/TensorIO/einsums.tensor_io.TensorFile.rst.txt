.. cpp:class:: TensorFile

   A handle on an ``.etn`` file.

   Writing, rewriting and reserving entries change the handle's own table until it commits, which
   ``close``, ``flush`` and the destructor do, and each entry operation (``rename``, ``swap``,
   ``copy``, ``remove``, ``restage``, ``compact``) does before it returns. A commit puts new data
   and a new table into space the file's last commit does not use and then rewrites the header, so a
   process that stops at any point leaves the file as its last commit left it. With
   ``--einsums:io:sync`` on, the default, a power loss does too. A handle refuses to commit over a
   file another handle has committed to since this one last read it.

   .. cpp:function:: void read_slab(std::string_view name, void *destination, const std::vector<std::pair<size_t, size_t>> &ranges) const

      Read a slab into raw memory, whatever the entry's element type.

      ``destination`` receives the slab's elements densely and in column-major order over the
      slab's own extents, which is the file's order, so no element is converted or moved: each
      contiguous run of the slab is one read. It must hold the slab's element count times the
      entry's element size. An empty range on any axis reads nothing.

      :param name: The entry.
      :param destination: Where the elements go.
      :param ranges: Per-dimension [start, end) ranges into the stored tensor.


   .. cpp:function:: void write_slab(std::string_view name, const void *source, const std::vector<std::pair<size_t, size_t>> &ranges)

      Write a slab from raw memory into an existing entry, whatever its element type.

      The mirror of ``read_slab``: ``source`` holds the slab's elements densely and in
      column-major order over the slab's own extents, and each contiguous run is one write.

      :param name: The entry, which must exist (see ``reserve``).
      :param source: Where the elements come from.
      :param ranges: Per-dimension [start, end) ranges into the stored tensor.


   .. cpp:function:: void rename(std::string_view old_name, std::string_view new_name)

      Give the entry ``old_name`` the name ``new_name``.

      Only the entry table changes, so a rename costs the same whatever the entry holds. It is
      committed before this returns. Renaming an entry to its own name does nothing.

      :throws std::runtime_error: when there is no entry ``old_name``, or the file is open for reading.
      :throws std::invalid_argument: when an entry is already named ``new_name``, or no entry can hold that name.


   .. cpp:function:: void swap(std::string_view first, std::string_view second)

      Exchange the names of the entries ``first`` and ``second``.

      Only the entry table changes, as for ``rename``. Afterwards ``first`` names what ``second``
      held and the other way round, which is the step a program that writes the next value of a
      tensor beside the current one takes to make the next value current. Swapping an entry with
      itself does nothing.

      :throws std::runtime_error: when either entry is missing, or the file is open for reading.


   .. cpp:function:: void replace(std::string_view source, std::string_view target)

      Make the entry ``source`` the entry ``target``, dropping what ``target`` held.

      Only the entry table changes, as for ``rename``, and in one commit: a crash leaves either
      both entries as they were or ``target`` holding what ``source`` held and no entry ``source``.
      The space ``target's`` old elements took is free from that commit on. This is the step that
      makes a value written beside the current one current, leaving no second entry behind.
      Replacing an entry with itself does nothing.

      .. versionadded:: 2.0.0

      :throws std::runtime_error: when there is no entry ``source``, or the file is open for reading.
      :throws std::invalid_argument: when no entry can hold the name ``target``.


   .. cpp:function:: void replace(const std::vector<std::pair<std::string, std::string>> &moves)

      Make each entry ``source`` the entry ``target``, for every pair of ``moves`` at once.

      Every pair is applied as by the overload for one pair, and all of them
      in one commit: a crash leaves either every entry as it was or every replacement made. This is
      the step that makes the values written beside several current ones current together.

      .. versionadded:: 2.0.0

      :param moves: The (source, target) pairs. A pair whose source is its target does nothing.
      :throws std::runtime_error: when a source is missing, or the file is open for reading.
      :throws std::invalid_argument: when no entry can hold a target's name, or a name is the source or the target of more than one pair, or both a source and a target, which would make the outcome depend on the order the pairs were applied in.


   .. cpp:function:: void copy(const TensorFile &source, std::string_view source_name, std::string_view name, size_t buffer_bytes)

      Copy the entry ``source_name`` of ``source`` into the entry ``name`` of this file.

      The entry ``name`` is created with the source's extents, element type and stored order when
      it does not exist. When it does, it must have the same extents and element type, keeps its own
      stored order, and holds its old elements until the copy is committed. The elements pass through a buffer of at most ``buffer_bytes``,
      so neither entry is ever held whole: entries stored in the same order are copied as runs of the file, and otherwise a box at a time,
      in runs of the source's order. ``source`` may be this file, and copying an entry of this file onto itself does nothing.

      :param source: The file holding the entry to copy.
      :param source_name: The entry to copy.
      :param name: The entry to copy it into.
      :param buffer_bytes: The most the copy holds in memory at once; zero takes ``--einsums:work-buffer-size``. A buffer smaller than one element holds one element.
      :throws std::runtime_error: when the source entry is missing or damaged, or this file is open for reading.
      :throws std::invalid_argument: when the entry ``name`` exists with other extents or another element type, or no entry can hold the name.


   .. cpp:function:: void remove(std::string_view name)

      Remove the entry ``name``, for every rank that holds one, and commit.

      Its data region becomes space later entries reuse; ``compact`` gives it back to the disk.

      :throws std::runtime_error: when there is no entry ``name``, or the file is open for reading.


   .. cpp:function:: void restage(std::string_view name, const std::vector<size_t> &order, size_t buffer_bytes)

      Store the entry ``name`` with its axes in ``order``, moving its elements, and commit.

      The elements are copied into a new region in the new order through a buffer of at most
      ``buffer_bytes``, and one commit then points the entry at it, so the entry holds its old layout
      or its new one whenever the program stops. The file needs room for a second copy of the entry
      while this runs. Restaging to the order the entry already has does nothing.

      :param name: The entry.
      :param order: The declared axis to store at each position, as ``stored_order`` returns it.
      :param buffer_bytes: As for ``copy``.
      :throws std::runtime_error: when there is no entry ``name``, or the file is open for reading.
      :throws std::invalid_argument: when ``order`` is not a permutation of the entry's axes.


   .. cpp:function:: void compact(size_t buffer_bytes)

      Rewrite the file without the space no entry uses.

      Every entry is copied, in its stored order and through a buffer of at most ``buffer_bytes``,
      into a new file beside this one, which then replaces it. The file is this one or the
      compacted one whenever the program stops, and the disk needs room for the entries' bytes
      while this runs. Another handle open on the file refuses to commit afterwards; backings,
      which open the file for each slab, see the compacted file at their next slab.

      :param buffer_bytes: As for ``copy``.
      :throws std::runtime_error: when the file is open for reading.
