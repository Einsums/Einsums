v2.0.0 Release#

What’s New#

  • Tensor storage order can now be selected per tensor at construction. Tensors are column-major by default, so the first index varies fastest.

    • Pass the order ahead of the name to build one row-major tensor, as in Tensor<double, 2> A(/*row_major=*/true, "A", 3, 3);. The order belongs to the tensor, so views and copies taken from it keep it.

  • Tensors are now based on a common implementation class to reduce the amount of code that needs to be maintained.

  • The QR decomposition routine now outputs the Q and R matrices, rather than the intermediates needed to compute these.

  • General eigendecomposition can now accept nullpointers for the eigenvectors you don’t want to calculate.

  • General eigendecomposition also only accepts complex tensors as outputs now.

  • HPTT plans can be saved and loaded in files. You no longer have to worry about wasting a bunch of time waiting for the better search methods. You can compile the transpose once and then load it in for subsequent program executions.

    • To support this, a new compile_permute function has been created, as well as overloads for the permute function that take plans as inputs.

    • The files are raw binary files to hopefully reduce the file size.

  • Einsums has its own argument parser and can handle configuration files.

  • norm can now handle vectors and can compute the spectral norm.

  • Disk tensors can now be used in certain linear algebra routines. Currently working are dot, true_dot, gemv, gemm, ger, gerc, and direct_prod. Work is being done to get gesv and truncated_syev working, though the implementation is not yet ready

  • Tensors can be cached to GPU. When tensors are cached, certain operations can use GPU algorithms instead of CPU algorithms to speed up calculations.

  • The einsum dispatcher now uses smarter rules for whether a tensor can be passed to a BLAS call.

  • Some tensors can now specify an allocator template parameter which will be passed to the vector.

What’s Removed#

  • The q function from the C++ and Python interfaces, and the r function from the Python interface.

  • CP and Tucker decomposition broke and were not able to be fixed. They have been moved to experimental.

  • h5cpp has been removed in favor of bare HDF5.

  • Einsums has its own argument parser now and no longer relies on cpp-argparse.

Bug Fixes#

  • Fixed a bug where GPU kernels were being launched with the block and grid sizes in the wrong order, leading to 31 inactive threads in a 32-thread warp.

Known Issues#

  • CP and Tucker decomposition do not work.

v1.1.2 Release#

What’s New#

  • You can now install the Python module where ever you want.

Bug Fixes#

  • Fixed a compilation error with HPTT using AVX512 intrinsics on incompatible systems.

v1.1.1 Release#

What’s New#

  • Batching over collections of tensors has been added to Python.

Bug Fixes#

  • Fixed a consistent issue where the launch parameters in almost all GPU kernels were swapped. The correct order should be <<<grid_specification, block_specification [, managed memory [, stream]]>>>.

  • Fixed a race condition in most of the GPU linear algebra functions.

  • Removed assertions in the device tensor headers and replaced them with if statements.

  • Fixed a bug in the Python in-core dot product contraction where the AB_prefactor was not actually used.

v1.1.0 Release#

What’s New#

  • Views of block and tiled tensors has been made easier.

  • TensorViews can be made from RuntimeTensors and RuntimeTensorViews so that compile-time rank can be assigned to them.

  • Buffer allocators for future projects. These allow users to limit the amount of memory used by Einsums.

  • Tensor permutations where the smallest stride is not 1.

  • The in-core generic algorithm is now much more performant.

  • The dispatching function for einsum is now more modular, so it is hopefully easier to maintain.

  • Einsum calls can now be batched over containers, such as vectors and arrays of tensors.

  • Linear algebra functions are now available in Python.

  • Complex implementations for several linear algebra functions that were previously missing, such as gees.

What’s Removed#

  • sort is no longer a valid alias for permute.

Bug Fixes#

v1.0.4 Release#

What’s New#

  • Indices no longer accepts things that aren’t indices as arguments. This means that a tensor that shadows an index name will throw a more reasonable error, rather than the esoteric mess that it had in the past.

Bug Fixes#

  • GPU tensor contractions now compile properly.

  • BlockTensors with a block of zero size will no longer cause segfaults with an einsum call.

v1.0.3 Release#

Bug Fixes#

  • Fixed how the Python module is linked to hopefully produce smaller binaries.

v1.0.2 Release#

Bug Fixes#

  • Fixed a typo in arange. It was throwing an error when valid inputs were passed.

  • Fixed a synchronization issue in the GPU tensor contractions

  • Fixed a bug in the in-place tensor-scalar operations for Tensor

  • Fixed a typo in truncated_svd that could cause compilation errors

  • Fixed the hip_catch family of functions so they would not construct temporary strings for every call. They now only construct temporary strings on failure.

v1.0.1 Release#

What’s New#

  • Modules can add their own command line arguments

  • More constructors for RuntimeTensors

v1.0.0 Release#

What’s New#

  • Arbitrary tensor views of pointers

  • Python support

  • Option and configuration maps

  • Better exception handling

  • Macros and base classes for common design patterns

  • Much more

What’s Changed#

  • The project has been restructured

  • sort is now permute

  • Several namespaces have been renamed

What’s Removed#

  • Temporarily removed Windows support

Bug Fixes#

  • Improved performance with some tensor contractions

v0.6.0 Release#

What’s New#

  • Element operations on GPU tensors

  • Macro-based exception system

  • True dot product for complex tensors. This does \(\mathbf{u}^*\mathbf{v}\), while the normal dot product does \(\mathbf{u}^T\mathbf{v}\), with the difference being that the first vector is conjugated.

  • Added in-line tensor arithmetic

  • Permutations for block and tiled tensors

  • Function tensors

Bug Fixes#

  • Miscellaneous block tensor fixes

  • GPU synchronization fixes

  • GPU linear algebra fixes

v0.5.0 Release#

What’s New#

  • Added block-diagonal tensors

  • Added Windows support

v0.4.1 Release#

What’s Removed#

  • MKL is no longer required.

Bug Fixes#

  • Fixed a performance issue with the einsum call.

v0.4.0 Release#

What’s New#

  • Added HIP-compatible tensors

  • Added GPU profiling capabilities

  • Tensors can be resized

  • More LAPACK routines have become available.

  • Some minor features

  • Added a job manager

What’s Removed#

  • LAPACKE and CBLAS are no longer dependencies for Einsums.
